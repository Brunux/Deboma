# Hardware validation reports

Raw output of `scripts/check-system.sh`, captured **on the machine itself**. They
are the evidence that this port is checked against the hardware and not only
against a chroot, where `/proc`, `/sys`, `dmesg` and `systemctl` describe the
host and every reading is meaningless.

Nothing here is generated by the build; each file is a copy of what the script
printed on the device.

A report has exactly one edit applied to it before it is committed: the
controller's MAC address is masked down to its OUI (`74:4C:A1:XX:XX:XX`). The
reports are published, and the hardware address of one particular machine is
evidence of nothing here — unlike `74:4C:A1`, which says whose radio it is.
Everything else, error lines included, is verbatim.

The reports from the earlier (sway) session were dropped when the Omarchy desktop
replaced it; they remain in this repository's git history.

## 2026-10-18-omarchy-desktop.txt

First report from the **Omarchy UI** (`UI=omarchy`; card written from `commit
85d32fc`), booted into the Hyprland desktop: **49 OK, 2 WARN, 1 FAIL**.

The FAIL and the one journal line worth chasing were both real, and both are
fixed (see `uis/omarchy/README.md`, "First boot"):

| line in the report | what it really was |
|---|---|
| `FAIL Hyprland reports configuration errors: [\n\t""\n]` | A **false FAIL**: `hyprctl -j configerrors` answers `[""]` — one *empty* string — when Hyprland 0.56.2's Lua loader has no error, and the check accepted only `[]`/`null`. It now drops the brackets and the blank entries before deciding. |
| `WARN ... foot[..]: config: .../theme/foot.ini:1: [colors-dark]: section declaration contains trailing characters` | Real: `omarchy-theme-set-templates` keeps each rendered line's terminator in gawk's `RT`. Debian's default `awk` is **mawk** (no `RT`), so every generated theme file collapsed into a single line. `gawk` is now in `uis/omarchy/packages.list`. |

The rest is the port passing on hardware: a dev-signed FIT with depthcharge's
`kern_guid`, `panfrost` with the backlight writable by `video`, `keyd` matching
the `cros_ec` keyboard while leaving the sleep key alone, Wi-Fi and `bluez`
powered, the ALSA `default` PCM, `greetd` on vt 7 running `omarchy-session`, the
Omarchy tree, theme and font families, and every declared package.

The two remaining WARNs are the ones expected on any boot: the `sbs-8-000b`
fuel-gauge noise, and no suspend recorded at report time (the Lock key was not
pressed).

Re-run on the card after the fixes above (hand-installed `gawk` +
`pulseaudio-utils`, fixed check script; **not** a clean rebuild, so it is not
committed as its own report): **57 OK, 2 WARN, 0 FAIL**, with the audio section
now reaching the card (`HiFi`, Headphones + Speaker sinks) because `pactl` is
present.

## 2026-10-19-emmc-desktop.txt

The same UI installed to the **internal eMMC** (`scripts/install-emmc.sh`, run
from the running card), audited against the Omarchy manual: **72 OK, 2 WARN,
0 FAIL**. `/` is `/dev/mmcblk0p3` and the kernel partition is the one the firmware
picked (`kern_guid` out of `/proc/cmdline`), so this is the install the machine
actually runs.

The twelve extra OKs over the first report are the checks the audit added. Nine
are the first round (`scripts/check-system.sh`, "Idle, lock and shell
environment"): the screensaver renderer and its seeded art, the lock screen's PAM
file and the running shell's `passwordPam`, `omasnap`, the shell-environment
helpers (`starship`, `bat`, `lua`, `notify-send`), `xkbcli` and `~/.bashrc`
sourcing Omarchy's rc. Three are from the second round, which audited the command
menu behind the manual's feature list: the generated row-hiding extension is in
place, the `Update > Channel` commands have no `/usr/bin` link (their rows died on
pacman), and `omarchy-update-time` has one (its row resyncs the clock). The link
count went `314 → 313` in the same step: two `omarchy-channel-*` links pruned, one
`omarchy-update-time` added.

Two checks came after this capture (`commit 2e3d8be`): the touchpad scrolls
naturally (the port's default, asked of the running compositor as
`input:touchpad:natural_scroll`) and `~/.local/state/omarchy/done/first-run-user`
exists (so a login no longer retries the un-vendored first-run steps). The same
machine reports **74 OK, 2 WARN, 0 FAIL** with them, after the change was applied
by hand; the file above is the tree that was actually installed, so it keeps its
own counts and the rebuilt image is what will carry these two.

The audit also corrected one check that was not wrong about the port but about
itself: `polkitd is active` was asserted with `systemctl is-active`, and
`polkit.service` is a **static** unit with no `[Install]` — polkitd is started by
D-Bus on the first authorization request and exits when there is nothing left to
answer, so an idle desktop legitimately reports it inactive. The first run of
this report caught that (a FAIL that no change of mine had caused, on a system
that had last used polkit during the lock-screen tests), and the check now asks
what has to hold: that the D-Bus service file exists and the daemon can be
started.

A second, smaller correction came out of re-taking this report while
`scripts/00-deps.sh` was installing: the declared-package check read `rsync` as
**missing**, because a `dpkg-query` taken while apt holds the database answers
"no packages found matching rsync" for a package that is installed. dpkg-query
cannot be asked to tell that apart from an unknown name (both exit 1), so the
section now SKIPs — naming the count — when a package manager is running, and the
report above was retaken with one idle. Same rule as polkit: a check that goes
red without a regression is worse than a check that abstains.

Like the card re-run above, this is **not** a clean rebuild: the audit's fixes
were applied by hand to the running system (the four new files, `apt install`
of `starship`/`libnotify-bin`/`lua5.4`/`file`/`iputils-ping`/`libxkbcommon-tools`,
the `bat` symlink, the `~/.bashrc` line, the theme directory, the menu extension
regenerated with the `Channel` rows hidden and the `Time` row back, the two stale
`omarchy-channel-*` links pruned) before the script ran, so the report documents
the *hardware* and the new checks, not the image as published. A `UI=omarchy`
rebuild carries the same fixes and is what the next release installs.

Both WARNs are the expected ones: the `sbs-8-000b` fuel-gauge noise, and no
suspend recorded in that boot — the Lock key had not been pressed since
power-on. Suspend itself is logind's own button path (`KEY_SLEEP` reaches it
because the keyd map leaves that key alone), and every boot starts at zero
cycles.
