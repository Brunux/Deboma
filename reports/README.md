# Hardware validation reports

Raw output of `scripts/check-system.sh`, captured **on the machine itself**. They
are the evidence that this port is checked against the hardware and not only
against a chroot, where `/proc`, `/sys`, `dmesg` and `systemctl` describe the
host and every reading is meaningless.

Nothing here is generated by the build; each file is a copy of what the script
printed on the device.

A report has exactly one edit applied to it before it is committed: the
controller's MAC address is masked down to its OUI (`74:4C:A1:XX:XX:XX`). The
reports are published, and the hardware address of one particular machine is
evidence of nothing here — unlike `74:4C:A1`, which says whose radio it is.
Everything else, error lines included, is verbatim.

## check-system-2026-10-16-card.txt

First report from a booted image — the 2-partition card, from before the layout
in `scripts/lib-cgpt.sh` was written to it — run as the desktop user:
**41 OK, 3 WARN, 2 FAIL**.

Read it with the outcome in mind, because three of those five non-OK lines were
bugs in the *checks*, fixed afterwards (commit `b8e038a`, "check-system: fix
three false results from the first real boot report"):

| line in the report | what it really was |
|---|---|
| `WARN firmware the kernel asked for and did not get: mediatek/mt8192/scp.img` | Benign. `mtk-scp` is a module, so it asks for the firmware from the initramfs three seconds before the root filesystem exists; the journal shows `Booting fw image ... size 309164` and `SCP is ready. FW version asurada_scp_v2.0.20536` right after. The check now reports the outcome of the load, not the first attempt. |
| `WARN no swap active (zram-tools should provide /dev/zram0)` | The swap *was* active: `Adding 1948372k swap on /dev/zram0`, priority 100, in every recorded boot. greetd's session PATH has no `/usr/sbin`, which is where `swapon` lives. The check now extends its own PATH and reads `/proc/swaps` as a second source. |
| `FAIL the MT8192 sound card is absent: 49 alsa_card.platform-sound alsa` | The card was there and working. PipeWire names it after the platform device, not after the codec, so the codec-name grep missed it; `HiFi` and both sinks appear a few lines below. The check now fails only when no card exists at all. |
| `FAIL declared but not installed: zstd upower` | Expected: the card predates those two entries in `packages/base.list`. |
| `WARN 349 error-priority line(s) this boot` | The `sbs-8-000b` fuel-gauge noise, upstream (Nura's own log has it too) and documented in AGENTS.md. |

The rest is genuine hardware validation, and it is why AGENTS.md states what it
states:

* `OK depthcharge substituted kern_guid` and a `cmdline` that **does** carry
  `cros_secure` (depthcharge adds it), which is what makes disabling
  `depthcharge-tools`' system hooks a correctness fix and not only a build fix;
* `OK device tree: Google Hayato rev1`, `root=UUID=` present, modules installed;
* `OK panfrost loaded`, `OK backlight writable by group video (664 video)` and
  the session user in that group (the `brightnessctl` udev rule);
* `OK keyd.service is active`, `keyd leaves the sleep key alone` and
  `keyd matched its keyboard: ... (cros_ec)` — the Lock key fix;
* `OK controller powered` (bluez), `OK card active profile: HiFi` with the
  Headphones and Speaker sinks (the UCM boot sequence), `OK alsa 'default' PCM
  available (pipewire-alsa)`;
* `OK 5 suspend/resume cycle(s) recorded in this boot`, `OK clock synchronised`,
  `OK sway configuration is valid`, every sway command present, and all four font
  families found (the tofu-icon fix).

## check-system-2026-10-16-card-2.txt

Second report, from the card rewritten with the three-partition layout of
`scripts/lib-cgpt.sh` and the fixed checks (image built from `c69d66f`):
**51 OK, 2 WARN, 0 FAIL**. Every non-OK line of the first report is gone, and
the three replaced checks now describe the hardware instead of the script:

* `OK firmware mediatek/mt8192/scp.img: requested before the rootfs was up, then
  loaded` — the outcome, not the retry;
* `OK swap active: /dev/zram0` — the PATH fix;
* `OK sound card: alsa_card.platform-sound` plus `OK ALSA codec:
  mt8192_mt6359_rt1015p_rt5682` — the card exists and the codec is the right one;
* `OK all 72 declared package(s) are installed` — `zstd`, `upower` and `iw` are
  in this image, and the wireless check proves it by reading `wlp1s0`.

The checks added the same day (commit `b8e038a` and after) passed on their first
real run, which is the point of taking a second report: `OK the kernel partition
holds a dev-signed FIT`, `OK the kernel partition /dev/mmcblk1p1`, `OK /boot is a
separate filesystem (/dev/mmcblk1p2) matching /etc/fstab`, `OK the running
kernel's vmlinuz is on /boot`, and `OK 1 suspend/resume cycle(s) recorded in this
boot` (the Lock key, pressed before the report).

The two remaining WARNs are the ones expected on any boot of this image:

| line in the report | what it is |
|---|---|
| `WARN regulatory domain not set (country 00)` | Environment, not a port bug: the world domain is what remains until NetworkManager or the access point's country IE sets one. The check now warns only when cfg80211 actually logs `failed to load regulatory.db` (the `wireless-regdb` bug it exists for) and otherwise prints an `info` line. |
| `WARN 198 error-priority line(s) this boot` | The `sbs-8-000b` fuel-gauge noise, upstream and present in Nura's own log. |

The layout is visible here too, and it is what the eMMC install reproduces:
`root /dev/mmcblk1p3 (UUID 376bd20d-…)`, `booted from removable storage`, `root
filesystem 13% used`.

The card was then brought from `c69d66f` to `54213ae` without being rewritten: the
committed tree was staged over it exactly as `build-rootfs.sh` stages it
(`git archive HEAD`, mode-normalized, `REVISION` and `/etc/debian-aarch64-revision`
updated), `xwayland` was installed so the card satisfies its own
`uis/sway/packages.list`, and its kernel partition was rebuilt and written again
with the quiet command line. That leaves the card equivalent to a build of
`54213ae` — the only differences between the two commits are files that live in
the staged tree plus the one package — which is what the eMMC install will copy.

When a later report is taken, add it here next to this one instead of replacing
it: the diff between two reports is what shows a regression.

## 2026-10-18-omarchy-desktop.txt

First report from the **Omarchy UI** (`UI=omarchy`; card written from `commit
85d32fc`), booted into the Hyprland desktop: **49 OK, 2 WARN, 1 FAIL**.

The FAIL and the one journal line worth chasing were both real, and both are
fixed (see `uis/omarchy/README.md`, "First boot"):

| line in the report | what it really was |
|---|---|
| `FAIL Hyprland reports configuration errors: [\n\t""\n]` | A **false FAIL**: `hyprctl -j configerrors` answers `[""]` — one *empty* string — when Hyprland 0.56.2's Lua loader has no error, and the check accepted only `[]`/`null`. It now drops the brackets and the blank entries before deciding. |
| `WARN ... foot[..]: config: .../theme/foot.ini:1: [colors-dark]: section declaration contains trailing characters` | Real: `omarchy-theme-set-templates` keeps each rendered line's terminator in gawk's `RT`. Debian's default `awk` is **mawk** (no `RT`), so every generated theme file collapsed into a single line. `gawk` is now in `uis/omarchy/packages.list`. |

The rest is the port passing on hardware: a dev-signed FIT with depthcharge's
`kern_guid`, `panfrost` with the backlight writable by `video`, `keyd` matching
the `cros_ec` keyboard while leaving the sleep key alone, Wi-Fi and `bluez`
powered, the ALSA `default` PCM, `greetd` on vt 7 running `omarchy-session`, the
Omarchy tree, theme and font families, and every declared package.

The two remaining WARNs are the ones expected on any boot: the `sbs-8-000b`
fuel-gauge noise, and no suspend recorded at report time (the Lock key was not
pressed).

Re-run on the card after the fixes above (hand-installed `gawk` +
`pulseaudio-utils`, fixed check script; **not** a clean rebuild, so it is not
committed as its own report): **57 OK, 2 WARN, 0 FAIL**, with the audio section
now reaching the card (`HiFi`, Headphones + Speaker sinks) because `pactl` is
present.
