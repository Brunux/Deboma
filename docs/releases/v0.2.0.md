# v0.2.0 — the Omarchy v4 desktop

The **Omarchy v4 desktop** (Hyprland + the Quickshell shell) replaces the sway session of
[v0.1.x](v0.1.1.md) on the **Google Hayato rev1** (ASUS Chromebook Detachable / Flip CM3 CM3200 —
MediaTek MT8192 "Asurada", `google-asurada`). The OS underneath is unchanged: Debian `forky`
`arm64`, mainline Linux 7.2.7 with Nura's (postmarketOS) config and patches, and the untouched
ChromeOS boot chain — depthcharge loads a **signed FIT "kpart"** from the kernel partition, and no
firmware is written.

The desktop is the maintainer's [Omarchy](https://github.com/omacom/omarchy) v4 tree, pinned and
ported, not reimplemented: same Hyprland Lua configuration, same Quickshell shell, same Tokyo Night
theme, same key bindings. What changed is the package manager and the platform underneath it, and
every deviation is documented in [`uis/omarchy/README.md`](../../uis/omarchy/README.md).

## What changed since v0.1.1

- **The session is Omarchy's.** `greetd` + `tuigreet` → `omarchy-session` → **UWSM** →
  **Hyprland 0.56.2**, which reads its configuration from `hyprland.lua` (v3's `hyprland.conf` is
  gone). The sway session and its `uis/sway` tree are removed from the repository.
- **The Quickshell shell**, pinned with the rest of the tree, owns the bar, launcher, command menu,
  dock, OSD, notifications, polkit agent, idle handling and clipboard. It runs against Debian's
  **Quickshell 0.3.2** plus the `qml6-module-qtquick*` set.
- **Pinned upstream:** `omacom/omarchy`, branch `quattro` @ `da2db1a2fe022089165b9edca3326886ad78dae2`
  (`4.0.0.alpha`). A curated subset (24 MB, 1318 files: definitions, Tokyo Night backgrounds,
  English translations) is vendored under `files/usr/share/omarchy/`, with `PROVENANCE.md` naming
  the pin.
- **`uis/omarchy/packages.list`** holds **135** Debian names, every one resolving on `forky/arm64`.
  The Arch → Debian mapping table in `uis/omarchy/README.md` records each substitution and why;
  the notable ones this release added are **`gawk`** (Debian's default `mawk` has no `RT`, which
  collapsed every generated theme file to one line), **`xwayland`** (Hyprland enables Xwayland by
  default; Debian's `hyprland` does not pull the server), **`libgtk-3-bin`** (`gtk-launch`, which
  the shell uses to start applications), **`curl`**, and the font set that gives the desktop a real
  `JetBrainsMono Nerd Font` alias and the Font Awesome / Material Design Icons glyphs Debian's
  `fonts-nerd-symbols` is stripped of.
- **Arch-only tooling is dropped, and the menu no longer offers it.** `pacman`, `yay` and the
  `omarchy-pkg-*` / `omarchy-update-*` / installer families are left off `PATH`; `setup.sh` now
  hides exactly the command-menu rows whose action calls one of them, through the shell's own
  `~/.config/omarchy/extensions/omarchy-menu.jsonc` extension point, so choosing a row cannot open
  a terminal that dies on `command not found`. What survives is what works here:
  `Install > Style > Theme`/`Background` and the `Update` menu. The hidden set is regenerated from
  the pinned menu on every build.
- **The Hayato quirks carry over** from the sway session: the `keyd` exclusions and `Ctrl+Alt`/
  `Search` virtual-terminal bindings, the `KEY_SLEEP` lock/suspend behaviour, the MT8192 ALSA UCM
  boot sequence, the backlight udev rule, the 4 GB RAM defaults and the Wi-Fi regulatory database.
- **The installed system was then audited feature by feature against the Omarchy manual, and four
  silent failures were fixed.** The idle **screensaver** needed `ttfx` (Omarchy's Rust
  terminaltexteffects, unpackaged on Debian: `files/usr/local/bin/ttfx` runs Debian's Python
  original in-process under that name) *and* the logo art seeded into
  `~/.config/omarchy/branding/`; the **lock screen** needed
  `/etc/pam.d/omarchy-lock-password` (the port ships Debian's stack, since upstream's
  `omarchy-apply-lock` writes Arch's); Print/`SUPER+SHIFT+S` needed **omasnap**, built from its own
  upstream tag by `scripts/build-omasnap.sh`; and the shell's aliases, zoxide/fzf and the starship
  prompt needed `~/.bashrc` to source `$OMARCHY_PATH/default/bashrc` (plus `starship`, `lua5.4`,
  `libnotify-bin` and `/usr/local/bin/bat` → `batcat`). `omarchy-transcode` came back with `file`.
  Every one of them failed with no error message at all, so `check-system.sh` now checks each one:
  see *Second audit* in [`uis/omarchy/README.md`](../../uis/omarchy/README.md).

## Validation

The evidence is the `check-system.sh` report taken **on the device**, kept in
[`reports/`](../../reports/).

- **First boot** of this UI: `reports/2026-10-18-omarchy-desktop.txt` — a card written from
  `commit 85d32fc`, reporting **49 OK, 2 WARN, 1 FAIL**. Both real findings are fixed in this
  release: `hyprctl -j configerrors` answering `[""]` (one empty entry, not a real error) and
  `omarchy-theme-set-templates` under `mawk`.
- **Desktop audit** on that booted card then found and fixed the rest: `gtk-launch` (the launcher
  and dock opened nothing), the Nerd Font family falling back to Noto Sans, the missing `curl`
  (weather), the dead `omacalc`/`omawrite` dock pins, Omarchy's own application entries never
  installed, and the menu rows that could not work. With those applied the card reports
  **59 OK, 2 WARN, 0 FAIL** — the WARNs being the upstream `sbs-8-000b` fuel-gauge noise and no
  suspend recorded yet in that boot.
- **The menu trimming was verified live** on the booted card by summoning the submenu over the
  shell's IPC and screenshotting it: `Install` went from thirteen rows to one, `Update` kept all
  six, and `Install > Style` kept `Theme` and `Background`.
- **The installed system was audited again** after `scripts/install-emmc.sh` put it on the internal
  disk, and `check-system.sh` reports **68 OK, 2 WARN, 0 FAIL** there
  ([`reports/2026-10-19-emmc-desktop.txt`](../../reports/2026-10-19-emmc-desktop.txt); the WARNs are
  the `sbs-8-000b` fuel-gauge noise and no suspend recorded in that boot). The audit's four fixes
  were applied to that running system by hand — the report documents the hardware and the checks,
  not the image — and the idle-screensaver → idle-lock → unlock chain and the capture overlay were
  verified on it: see *Second audit* in [`uis/omarchy/README.md`](../../uis/omarchy/README.md).
- The image published here is the **clean rebuild** of this tree (the fixes above applied by the
  build, not by hand), and its own report is captured the same way and kept beside the first one.

## Assets

| asset | what it is |
|---|---|
| `google-asurada.img.xz` | 6 GiB disk image: the three ChromeOS GPT partitions (kernel, `/boot`, root), ready for `dd` |
| `google-asurada-rootfs.tar.zst` | the same root filesystem as a tarball (with `/boot` inside), for writing your own card with `scripts/write-sd.sh` |
| `google-asurada.vmlinuz.kpart` | the signed FIT kernel partition of that image; it embeds the image's `root=UUID`, so it belongs to this image and no other |
| `SHA256SUMS` | SHA-256 of the three assets |

```sh
sha256sum -c SHA256SUMS
xz -dc google-asurada.img.xz | sudo dd of=/dev/mmcblk1 bs=4M conv=fsync
```

On the Chromebook: developer mode, `crossystem dev_boot_usb=1 dev_boot_signed_only=0`, insert the
card, turn it on and pick **external disk** in the firmware menu. It comes up silently to a greetd
prompt: user `brunux`, password `debian`, passwordless sudo — change the password before using it
for anything real. (`scripts/install-emmc.sh` then installs it to internal storage.)

## What it does not carry

Unchanged from v0.1.x: the artifact is sanitized and asserted clean (`scripts/lib-dist.sh`). No
Wi-Fi profiles, no SSH host keys, no `machine-id`, no personal files — the machine identity and the
SSH host keys are generated on first boot.

## Known limitations

- **The `omarchy-pkgs` applications are not in this release** — `omawrite`, `omacalc`, `owe`, the
  AI/gaming/web-app installers and the rest of that set are deferred to a later release (F8 in
  [`docs/plan-omarchy.md`](../../docs/plan-omarchy.md)), and the menu hides their rows rather than
  offering them broken. The one exception is **omasnap**, which this release builds from source
  because the capture key `exec`s it and nothing else provides a capture overlay.
  `Owe.LockFeed` goes with the deferred set, so the lock screen's media feed is empty; the lock
  screen itself works, and locks.
- **Quickshell 0.3.2 logs `Unrecognized pragma "OmarchyLoadPatch"`**: that is a pragma from
  Omarchy's patched Quickshell, and its patch-loading hook is inert on Debian's stock build.
  Nothing shipped here depends on it.
- Quickshell/QML warnings (`Binding loop ... "height"` in the network panel, `QString::arg:
  Argument missing` on a few translations, the portal "already associated" line) are upstream and
  cosmetic.
- The image is 6 GiB. A larger card keeps the space after `p3` unused; writing the tarball with
  `scripts/write-sd.sh` sizes `p3` to the whole card.
- Artifacts are not byte-reproducible yet (FIT timestamp, filesystem UUIDs).
- Battery percentage is the capacity reading only; the gauge reports `Unknown chemistry: OTC0` and
  spams the journal on upstream kernels — Nura's own log has the same lines.
